# HUS LLM L3 Implementation Plan

**Goal:** Register a RAG-grounded Gemini adapter behind L2, accepting output only
after strict JSON/evidence checks and preserving all canonical data.
**Architecture:** Build an immutable allowlisted bundle from L2 context, combine
it with a versioned system prompt, call the L1 client, validate raw JSON against
the same bundle, then return the existing L2 result types. No UI or L4 concurrency.
**Tech Stack:** Existing Python, Pydantic, httpx and pytest; no new dependencies.
**Spec:** User-selected L3 table and ../specs/2026-11-10-hus-rag-gemini-design.md.
**Execution:** Native on `hus-llm-rag`; preserve existing WIP. No commit/push/live
provider call or global mode/key change is authorized by this implementation step.

## Constraints and review focus

- Both enable gates, eligibility and independent F3 consent stay in L2.
- Send only question, selected-snapshot scope, whitelisted facts and selected
  quotes/review/origin/IDs. Never serialize arbitrary citation metadata, provenance,
  accounts, transcripts, history, local paths, URLs or configuration keys.
- Verify source identity/scope before sending. Canonical faults fail closed;
  invalid provider output or budget overflow falls back to the original answer.
- Budget: complete prompt <=12,000 Unicode characters; raw output <=8,192 characters;
  request output cap stays 1,024 tokens. No silent truncation; reported completion
  usage over 1,024 also rejects the result. These are controls, not latency SLOs.
- F1/F3 raw JSON has `kind=rewrite`, `points` with `text`, `citation_id`,
  `anchor_quote`. All selected citation IDs must be covered; each anchor must be an
  exact source span. Sensitive numbers/codes/versions must come from that point's
  cited evidence/scope. HTML/links/extra keys/unrecognized IDs are rejected.
- Coverage is structural (citations and sensitive atoms), not proof of semantic
  entailment/completeness. Keep LLM disabled and require L5 content review.
- F2 raw JSON has `kind=facts`, `style`, `fact_keys`, `citation_ids`; exact expected
  key/ID coverage, no new values/text. Existing L2 renders the whole canonical block.
- JSON duplicate keys, NaN, non-object/fenced/prose-wrapped output, wrong scalar
  types, truncated/provider-tool output, omitted actual model all fail safely.
- Returned model/usage are read from provider envelope, not generated JSON.
  Prompt hash traces the exact messages; safe fallback codes never contain body/key.
