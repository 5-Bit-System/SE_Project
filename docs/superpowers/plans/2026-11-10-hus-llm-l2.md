# HUS LLM L2 Implementation Plan

**Goal:** Implement the user-selected L2 permission and response contract, including F2,
without implementing the L3 prompt/output validator or L4 UI.

**Architecture:** Post-process the canonical chat answer behind both enable flags.
A server-injected typed adapter is the L3 extension point; absent adapter returns
`pipeline_unavailable`. Never invoke the L1 HTTP client directly from L2.

**Tech Stack:** Existing Python/Pydantic/FastAPI and pytest; no dependencies added.
**Spec:** User's L2 table and ../specs/2026-11-10-hus-rag-gemini-design.md.
The user selected L2 only; previous broader design questions do not block this slice.
Execution: native in the current named branch; no commit/push or worktree change.

## Global constraints

- Add strict `allow_llm_rewrite=false`, independent of F3 permission.
- Either flag off: byte-equivalent default response serialization; no metadata added.
- Both flags on: metadata explains used/model/fallback, including skipped requests.
- Only answered F1/F2/F3 with citations may reach the adapter; F3 needs both rights.
- Basic chat, clarification, missing sources/information never call an adapter.
- Preserve `hus_answer`, facts, every citation/quote/URL/hash/review, and F2 data.
- Callback receives deep copies; exceptions cannot corrupt the canonical response.
- F2 callback result is presentation style only; render the entire original fact block.
- Default settings remain lexical and LLM disabled; no live calls or key changes.

## Review focus

- Strict boolean rejects strings, integers and null on the actual API boundary.
- Disabled flags ignore unrelated invalid/missing LLM configuration and do no I/O.
- A callback mutating nested source/facts must not alter original request/response.
- F2 free text is rejected; unknown/conflict/unresolved remain in the canonical block.
- Provider/config errors are sanitized; canonical-data errors remain HTTP 503.
