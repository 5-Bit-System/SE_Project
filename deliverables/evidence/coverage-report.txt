3. RESIDUAL RISK & NON-GOALS DOCUMENTATION
- Expected Status Opt-In & UI Limitation: Compare-and-Set concurrency protection is activated when client passes expected_status. Legacy clients that omit expected_status execute unconditional updates (by design for backward compatibility). Furthermore, the current frontend UI does not submit expected_status; CAS protection is currently operational and verified at backend API and service layers, awaiting frontend UI parameter binding.
- Database Schema Governance: The database check constraint accounts_role_check was formally updated via versioned Alembic migration hus_20261111_14 (database/hus_alembic/versions/20261111_14_reviewer_role.py) to officially allow 'reviewer' alongside ('student', 'teacher', 'admin').
- Reviewer Provisioning Limitation: Endpoint app/api/auth.py:179 currently restricts user-facing role assignment to {'student', 'admin'}. Reviewer accounts must currently be provisioned manually or via database migration/scripts.
- Migration Downgrade Prerequisite: Alembic downgrade to hus_20261105_13 will fail if accounts with role='reviewer' remain in the database; operator must purge or reassign reviewer accounts prior to downgrade.
- Test Database Prerequisite: HUS_TEST_DATABASE_URL target database must have migration hus_20261111_14 applied (via `uv run alembic upgrade head`) before running test suites.
